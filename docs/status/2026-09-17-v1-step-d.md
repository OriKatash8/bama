## 1. Push for price changes

**The finding:** a price change sent no push. The 💰 chat line is a system message, and
`onNewChatMessage` skips system messages (`functions/src/notifications/triggers.ts:45`). Nothing
listens on `paymentRequests` either.

**The fix, as you decided:**
- `createPaymentRequest` writes a notification for `toUserId` **after** its transaction commits,
  so a refused request notifies nobody.
- It works in both directions: the client asking the pro, and the pro asking the client.
- The type is `system`. That type can't be muted, which fits because it's about money, and the
  app already opens the chat when it's tapped.
- **Wording:**
  - to the pro: "💰 הלקוח/ה ביקש/ה שינוי מחיר בפרויקט "…""
  - to the client: "💰 בעל/ת המקצוע ביקש/ה שינוי מחיר בפרויקט "…""

  The pro's wording is neutral rather than "counter", because after confirmation he can raise a
  change unprompted.

**Checked:**
- a wiring test (`notify` runs after `runTransaction`, with type `system`);
- `scripts/probe-repricing.mjs` §8 on the emulators:
  - the pro gets exactly one notification for a client request;
  - the client gets one for a pro request;
  - the sender gets none;
  - a refused (still-pending) request adds none.

Confirmation sends no push, per your decision; the chip is the signal.

## 2. What was built

**CandidateReviewCard** (client only)
- **Position:** pinned under the header as part of it. Same white, flush edges, a hairline
  underneath, above the message list.
- **Rows:** one per pro still under review (`isPendingReview`: accepted **and** pending): avatar,
  name, role(s), price, then רלוונטי / לא רלוונטי / שינוי מחיר.
- **Disappears** once nobody is under review.
- **Blocked by a pending price change**, on any role of that pro (the same key as the server
  lock):
  - **waiting on the pro:** "ממתין לתשובת {name}" is shown. רלוונטי and שינוי מחיר are disabled;
    לא רלוונטי stays enabled.
  - **waiting on the client:** "{name} הציע/ה מחיר חדש — לצפייה ותשובה ‹" is a link to the payments
    section of project details, where the client answers.
- **Name not loaded** (or the user doc is missing): the row shows "טוען…" and **all three buttons
  stay disabled** until the name arrives.
- **רלוונטי** asks through `confirmDialog`, then calls `confirmCandidate`. `Alert.alert` is never
  used.
- **לא רלוונטי** opens a reason sheet: an optional reason of up to 500 characters, sent privately.
  The client is told if the reason couldn't be delivered.
- **שינוי מחיר** opens a price sheet: a role picker when the pro holds several roles, and the
  1–50000 check on the client.
- Server refusals show as readable toasts.

**CandidateStatusChip** (pro only)
- **Amber** "ממתין להחלטת הלקוח/ה" while pending. **Green** "אושרת לפרויקט" once confirmed.
  **Gone** when the project goes `in_progress`.
- Shows his own price, counting a bundle once.
- If the client asked him for a price change, a link opens it. If he asked, it says it's waiting
  for the client.
- Legacy hires (no `review` field) show no chip.

**ChatRoomScreen**
- The project read is now live (`onSnapshot`), so the chip follows the project's status.
- Whether you see the card or the chip is decided by your role on the project, not by the app
  mode.
- The 🎬 crew message has its own pill.

### Found and fixed during the pass
**The name line rendered reversed in English**
(`en-00-BUG-before-fix-name-line-reversed.jpg`). "{name} proposed a new price…" starts with the
name, so with a Hebrew name the browser treated the whole line as right-to-left. Every line that
contains a name now sets its writing direction from the UI language (`d6404c3`). A test covers
it, and two mutations (removing it, or setting it to `auto`) were caught. `en-01` shows the fixed
line. Hebrew lines with English names were exposed to the same bug and get the same fix.

### Seed artifacts, not problems in the new UI
- **Pro's chat shows a red `listenToProjectFee failed` overlay.** The seed writes no fee docs
  (a real hire does), and reading a missing fee doc is denied by the rules. It was dismissed
  before the chip screenshots.
- **Project details shows B's user id instead of his name in the request.** That screen reads
  member names from `filledSlots`, which the seed filled with placeholder entries for the
  notification guard. Real hires put the pro there.

### Notes for your review
- **The card is tall.** With two pending pros it takes about 40% of a phone-height screen, and
  the rest stays scrollable. With more than three pros the rows scroll inside a capped area. If
  that's too much, a collapsed "2 אנשי צוות ממתינים ›" header with expandable rows is the natural
  next step. It isn't built.
- **Price position in RTL:** the price sits at the far left of the row, opposite the name, a
  mirror of the English layout.
- **Browser session:** the browser profile was signed in as bobo@gmail.com on localhost:8081. As
  you agreed, it was signed out. Each throwaway account signed in and out in turn, the last one
  was signed out at the end, and the app language setting was restored to Hebrew. You'll need to
  sign back in to bobo.
